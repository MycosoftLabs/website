# DIRTNet
## Decentralized Edge Intelligence Architecture
### A distributed autonomous sensing data center for live environmental and biological learning

**Version:** 0.1 — mathematical and algorithmic reference architecture  
**Date:** 16 July 2026  
**Canonical expansion:** **DIRTNet = Decentralized Edge Network**  
**System relationship:** DIRTNet coordinates MycoBrain devices, edge accelerators, MDP, Mycorrhizae, MycoSpeak, NLM, MINDEX, MYCA, AVANI, NatureOS, and FUSARIUM.

---

## Executive thesis

A conventional data center centralizes compute around stored data. A DIRTNet node puts compute, sensing, model inference, local memory, cryptographic identity, and network participation at the point where new data is created. A fleet of such nodes becomes a **distributed autonomous sensing data center** embedded across soil, air, water, organisms, machines, infrastructure, laboratories, and mobile platforms.

DIRTNet is therefore not a radio protocol, not a blockchain, and not a cloud service. It is the **coordination fabric** that lets heterogeneous edge nodes:

1. observe physical and biological reality;
2. validate and summarize evidence locally;
3. infer state with NLM models close to the signal;
4. continue operating during network partitions;
5. route high-value information over constrained links;
6. synchronize records and model knowledge when contact returns;
7. prove data lineage with SHA-256, signatures, hash chains, and Merkle roots;
8. coordinate local and global MYCA agents under AVANI policy;
9. expose civilian scientific workflows through NatureOS and defense workflows through FUSARIUM.

The central innovation is not merely “edge AI.” It is the composition of **edge sensing + local state inference + partition-tolerant synchronization + cryptographic evidence + biological transduction + governed multi-agent coordination**.

## 2. System model

Let DIRTNet at time \(t\) be a time-varying directed multigraph

\[
\mathcal{D}_t=(V_t,E_t,\mathcal{T},\mathcal{S},\mathcal{M},\mathcal{P}),
\]

where:

- \(V_t\) is the set of edge nodes, gateways, relays, and platform services;
- \(E_t\) is the set of available communication links;
- \(\mathcal{T}\) is the set of transport profiles;
- \(\mathcal{S}\) is the distributed sensor and evidence state;
- \(\mathcal{M}\) is the model, prototype, and policy inventory;
- \(\mathcal{P}\) is the provenance and governance state.

### 2.1 Edge-node state

Node \(i\) has state

\[
X_i(t)=\left(
C_i,E_i,B_i,S_i,Q_i,L_i,\theta_i,K_i,A_i
\right),
\]

where:

- \(C_i\): compute capacity and current utilization;
- \(E_i\): energy state and harvest forecast;
- \(B_i\): local storage and pending network queue;
- \(S_i\): sensor capabilities and calibration state;
- \(Q_i\): evidence-quality and device-health state;
- \(L_i\): append-only local evidence log;
- \(\theta_i\): local model and prototype inventory;
- \(K_i\): cryptographic identity and trusted key material;
- \(A_i\): local AVANI authority and action envelope.

### 2.2 Link state

Link \((i,j)\) has

\[
Y_{ij}(t)=\left(
R_{ij},\ell_{ij},p_{ij},e_{ij},d_{ij},u_{ij}
\right),
\]

where \(R\) is bitrate, \(\ell\) latency, \(p\) loss probability, \(e\) energy cost per bit, \(d\) duty-cycle or regulatory constraint, and \(u\) availability.

A LoRa link and an Ethernet link are not interchangeable edges. DIRTNet treats the transport as a constraint on what information should be sent, not merely how bytes move.

### 2.3 Local autonomy invariant

A node should retain a bounded useful operating mode when disconnected:

\[
\operatorname{Capability}_i(\text{partition})\ge \mathcal{C}_{min,i}.
\]

At minimum this includes sensing, local health checks, local event detection, append-only evidence storage, policy-limited action, and later synchronization.

## 3. DIRTNet layer model

### 3.1 Physical sensing layer

DIRTNet carries six NLM physical modalities and their contextual channels:

- **BlueSight:** optical, scene, depth, motion, radar, LiDAR, WiFiSense, and blue-light biological response;
- **SINE:** acoustic, hydroacoustic, airborne, mechanical, impulse, seismic, animal, vessel, propeller, and machine sound;
- **GANDHA:** VOC, VSC, gas, humidity, temperature, pressure, airflow, particles, spectroscopy, and odor signatures;
- **FCI / Fungi Compute:** mycelial bioelectric and impedance channels plus controlled stimuli;
- thermal, mechanical, magnetic, radiation, weather, position, and device-health channels.

### 3.2 Deterministic device layer

MycoBrain and equivalent controllers perform:

- sensor discovery and capability publication;
- calibration application;
- timebase and sequence assignment;
- local artifact detection;
- low-latency control and safety interlocks;
- buffering and MDP frame transport;
- radio and gateway coordination.

### 3.3 Edge inference layer

Higher-capacity nodes—Jetson, Hailo, NPU, TPU, GPU, CPU, or FPGA—perform:

- local BlueSight detection/segmentation/tracking;
- local SINE DSP and acoustic embedding;
- local GANDHA compensation and odor classification;
- local FCI motif/state inference;
- NLM posterior state and forecast;
- compression, prototype retrieval, anomaly detection, and event prioritization;
- selected MYCA agent and tool execution.

### 3.4 Semantic message layer

- **MDP** moves framed device bytes, status, commands, and heartbeats.
- **Mycorrhizae Protocol** provides the shared channel and message schema across devices, MINDEX, MYCA, NatureOS, and FUSARIUM.
- **MycoSpeak** is the compact operational vocabulary for intents, device state, alerts, and local commands.
- **NMF / RootedNatureFrame** provides the scientific, model-ready evidence contract.

### 3.5 Adaptive transport layer

DIRTNet selects among:

- local buses and UART/USB/CAN;
- BLE and Wi-Fi;
- LoRa point-to-point;
- LoRaWAN managed gateways;
- Meshtastic-compatible off-grid mesh participation;
- Ethernet, LTE/5G, satellite, MQTT, and device relays;
- acoustic or optical links for special environments.

### 3.6 Federated memory and control layer

MINDEX stores content, lineage, checkpoints, models, prototypes, and outcomes. MYCA places tasks and coordinates agents. AVANI controls evidence admission, model promotion, command authority, and reversible action.

### 3.7 Platform layer

NatureOS and FUSARIUM expose the same underlying evidence and intelligence through distinct admission, policy, and operator surfaces.

## 4. The data sensor as a decentralized data-center node

A DIRTNet device is not only a sensor. It implements five data-center functions locally:

1. **acquisition:** generates new data unavailable in historical corpora;
2. **compute:** transforms raw measurements into features, events, states, and forecasts;
3. **storage:** preserves raw or selected evidence during disconnection;
4. **networking:** participates in local routing and opportunistic synchronization;
5. **governance:** authenticates, validates, prioritizes, and constrains local action.

Define node intelligence yield over interval \(T\) as

\[
Y_i(T)=\frac{
\sum_{m\in \mathcal{O}_i(T)} V(m)\,Q(m)\,N(m)
}{E_i(T)+\lambda_B B_i(T)+\lambda_C C_i(T)},
\]

where \(V\) is decision value, \(Q\) evidence quality, \(N\) novelty, \(E\) energy, \(B\) transmitted bytes, and \(C\) compute cost.

This is a more appropriate optimization objective than maximizing raw data volume.

## 5. Bitcoin-derived audit primitives—used precisely

DIRTNet borrows architectural primitives from Bitcoin without claiming that environmental telemetry is money or that proof-of-work is necessary.

| Bitcoin primitive | DIRTNet analogue | Purpose |
|---|---|---|
| independent node | autonomous edge sensor/compute node | local validation and resilience |
| wallet key | device or service signing key | cryptographic identity and command authority |
| transaction | signed observation, inference, model update, or command result | immutable evidence event |
| mempool | local pending store-and-forward queue | disconnected operation and later relay |
| block | bounded evidence epoch | compact batch commitment |
| Merkle root | epoch evidence root | efficient proof of inclusion |
| block header chain | parent-root checkpoint lineage | ordered tamper-evident history |
| simplified payment verification | compact observation inclusion proof | verify a record without downloading all raw data |
| miner/block producer | epoch assembler or validating gateway | batch, validate, and checkpoint evidence |
| full node | MINDEX/gateway validator | retain and independently verify a larger evidence set |

### 5.1 Deliberate non-equivalence

Routine DIRTNet operation should **not** use Nakamoto proof-of-work. Bitcoin's proof-of-work solves an open, adversarial monetary consensus problem. A permissioned environmental fleet normally has device identities, operational authorities, physical deployment records, and bounded trust domains. Proof-of-work would add energy and latency without solving the actual problem.

Recommended DIRTNet consensus is:

- signatures at the record source;
- independent validation at gateways or MINDEX services;
- deterministic schema, calibration, sequence, and policy checks;
- Merkle epoch commitments;
- quorum or notary signatures for federated checkpoints;
- optional external public timestamp anchoring for selected high-value roots.

### 5.2 Evidence mining

The term **evidence mining** may be used carefully: a DIRTNet node expends sensing, compute, storage, and energy to discover and validate new physical evidence. It does not mint currency. The “reward” is scientific or operational information gain.

## 6. Cryptographic record and checkpoint mathematics

Let \(C(x)\) be a canonical deterministic serialization of record \(x\). For node \(i\), sequence \(k\):

\[
h_{i,k}=H(
\texttt{DIRTNET-RECORD-v1}\Vert i\Vert k\Vert t_{i,k}\Vert
h_{i,k-1}\Vert H(C(payload_{i,k}))\Vert H(C(context_{i,k}))
),
\]

with \(H=\operatorname{SHA256}\).

The node signs:

\[
\sigma_{i,k}=\operatorname{Sign}_{sk_i}(h_{i,k}).
\]

Verification is

\[
\operatorname{Verify}_{pk_i}(h_{i,k},\sigma_{i,k})=1.
\]

### 6.1 Epoch root

For ordered record hashes in epoch \(e\):

\[
R_{i,e}=\operatorname{MerkleRoot}(h_{i,k_1},\ldots,h_{i,k_n}).
\]

### 6.2 Federated checkpoint

For nodes included in a checkpoint:

\[
R_e=H(
\texttt{DIRTNET-CHECKPOINT-v1}\Vert e\Vert
\operatorname{MerkleRoot}(H(i_1\Vert R_{i_1,e}),\ldots,H(i_q\Vert R_{i_q,e}))
\Vert R_{e-1}\Vert H(policy_e)
).
\]

Checkpoint signers produce

\[
\Sigma_e=\{\operatorname{Sign}_{sk_j}(R_e):j\in \mathcal{Q}_e\}.
\]

AVANI defines the quorum rule by mission and evidence class. A low-risk public science stream may require one trusted gateway signature; high-consequence mission evidence may require multiple independent signers.

### 6.3 Inclusion proof

A proof \(\pi(h_{i,k},R_{i,e})\) has \(O(\log n)\) sibling hashes. Verification permits a remote analyst to prove that one record belongs to a signed epoch without transferring the full epoch.

### 6.4 Integrity does not equal truth

A valid signature and Merkle proof establish who produced a record, what bytes were committed, and whether it changed. They do not establish correct calibration, legitimate sensor placement, valid labels, or correct inference. Scientific validity remains a separate AVANI and quality-control problem.

## 7. Device identity and wallet-like key architecture

Each node should have at least three key classes:

1. **identity key:** long-lived node identity, preferably secure-element or TPM protected;
2. **record-signing key:** rotated operational key for observations and checkpoints;
3. **command-authority keys:** separate keys and scopes for accepting commands or model updates.

The manifest binds:

\[
NodeID=H(pk_{identity}\Vert device\_class\Vert manufacturing\_record).
\]

Key rotation records are signed by the prior authorized key or by a provisioning authority. Compromise must permit revocation without invalidating historical evidence.

The proposed node contract is `schemas/dirtnet_node_manifest_v0_1.schema.json`.

## 8. DIRTNet message contract

The proposed signed message includes:

- UUID message identity;
- node identity and monotonically increasing sequence;
- hybrid logical clock;
- observation time and uncertainty;
- Mycorrhizae channel;
- message type, priority, and TTL;
- payload hash and optional content address;
- context, calibration, quality, drift, and OOD;
- transport profile, hop limit, path, acknowledgment mode, and dedupe key;
- previous record hash, current record hash, signer, signature, and epoch root.

The machine-readable schema is `schemas/dirtnet_message_v0_1.schema.json`.

### 8.1 Duplicate identity

Define

\[
dedupe(m)=H(node\_id\Vert node\_sequence\Vert content\_hash).
\]

Relays cache recent dedupe keys. A repeated packet may refresh delivery acknowledgment but must not create a second observation.

### 8.2 Message priority

A bandwidth-aware priority score is

\[
P(m,t)=
\frac{
w_u U(m)+w_v V(m)+w_n N(m)+w_q Q(m)+w_f F(m,t)+w_d D(m)
}{\epsilon+\operatorname{Airtime}(m)+\lambda_E\operatorname{Energy}(m)},
\]

where:

- \(U\): urgency;
- \(V\): decision value;
- \(N\): novelty;
- \(Q\): evidence quality;
- \(F\): freshness;
- \(D\): source or modality diversity contribution.

A critical alert may transmit immediately; raw video may wait for high bandwidth while its compact detection event transmits over LoRa.

## 9. Transport-neutral routing

For route \(r=(v_0,\ldots,v_k)\), define cost

\[
J(r,m)=\sum_{(i,j)\in r}
\left[
\alpha\ell_{ij}+
\beta\frac{|m|}{R_{ij}}+
\gamma e_{ij}|m|+
\delta(-\log(1-p_{ij}))+
\zeta\,Congestion_{ij}
\right]
+\rho\,Risk(r,m).
\]

Choose

\[
r^*=\arg\min_{r\in\mathcal{R}_{admissible}(m)}J(r,m).
\]

The admissible route set enforces classification, location privacy, authority, and export policy. A high-value message may be replicated over multiple independent paths. Routine telemetry should not waste scarce airtime.

### 9.1 Transport profiles

- **LoRa:** compact, low-duty-cycle events and health messages;
- **LoRaWAN:** gateway-managed regional device fleets and network-server integration;
- **Meshtastic:** resilient off-grid multi-hop participation and opportunistic relay;
- **Wi-Fi/Ethernet:** raw windows, images, model packages, and fast sync;
- **LTE/satellite:** long-distance backhaul with cost and availability constraints;
- **acoustic/optical:** special underwater or line-of-sight applications.

### 9.2 Store-and-forward

A node queues messages during disconnection. The queue is not FIFO alone; it is a priority queue over \(P(m,t)\), with retention rules preserving high-value evidence and gracefully dropping reproducible low-value telemetry first.

## 10. Partition-tolerant time and synchronization

### 10.1 Hybrid logical clocks

A hybrid logical clock is

\[
HLC_i=(p_i,l_i,i),
\]

where \(p_i\) is physical time, \(l_i\) is a logical counter, and \(i\) is node identity. It preserves causal ordering while retaining a relation to wall time.

Sensor observation time remains separate from ingestion time and carries uncertainty. A device with poor GNSS/NTP lock must not silently present false precision.

### 10.2 Anti-entropy synchronization

Nodes first exchange compact sync manifests containing epoch IDs, roots, sequence ranges, model inventories, and queue summaries. If roots match, no records move. If roots differ, a Merkle tree walk or range comparison identifies missing subsets.

Let \(R_A\) and \(R_B\) be roots. Reconciliation seeks

\[
\Delta_{A\rightarrow B}=L_A\setminus L_B,
\qquad
\Delta_{B\rightarrow A}=L_B\setminus L_A,
\]

without enumerating all records when possible.

The proposed sync schema is `schemas/dirtnet_sync_manifest_v0_1.schema.json`.

### 10.3 Merge semantics

- immutable observations: set union by content identity;
- lineage: retain all valid branches rather than overwrite;
- labels and annotations: multi-value or CRDT register with author/time/provenance;
- device configuration: AVANI-authorized last-writer according to HLC and command authority;
- model promotion: explicit signed version state machine, never generic last-writer-wins;
- deletions: signed tombstones governed by retention and privacy policy.

### 10.4 Convergence

For replicas \(i,j\), eventual convergence requires

\[
\Pr\left(L_i(t+T)=L_j(t+T)\mid \text{sufficient contacts and admissible transfer}\right)\rightarrow1.
\]

The qualification matters: policy may intentionally prevent full replication across compartments.

## 11. Distributed task placement

A task \(\tau\) has compute demand \(c_\tau\), memory demand \(m_\tau\), input data locations \(D_\tau\), deadline \(d_\tau\), sensitivity \(s_\tau\), and expected value \(v_\tau\).

Binary placement variable \(x_{i\tau}\in\{0,1\}\) indicates execution on node \(i\).

\[
\min_x \sum_{i,\tau}x_{i\tau}
\left[
\alpha L_{i\tau}+\beta E_{i\tau}+\gamma B_{i\tau}+\delta R_{i\tau}
\right]
\]

subject to

\[
\sum_\tau x_{i\tau}c_\tau\le C_i,
\quad
\sum_\tau x_{i\tau}m_\tau\le M_i,
\quad
Completion_{i\tau}\le d_\tau,
\quad
Admissible(i,\tau)=1.
\]

Where feasible, processing should move to data rather than moving all raw data to a central model.

### 11.1 MYCA scheduler

MYCA may place:

- a BlueSight detector on an Agaric or Hyphae node;
- a SINE acoustic classifier on Psathyrella;
- a GANDHA odor model on SporeBase;
- an FCI motif detector on Mushroom 1 or a lab rig;
- a cross-site synthesis agent on a gateway or central service.

AVANI constrains which model, tool, command, and data scope are legal for each node.

## 12. Local NLM and federated learning

### 12.1 Local posterior

Node \(i\) estimates

\[
b_i(s_t)=p_{\theta_i}(s_t\mid y_{i,1:t},c_{i,1:t}).
\]

It emits compact state, anomaly, uncertainty, and evidence handles rather than necessarily transmitting raw streams.

### 12.2 Model-update object

After local training, node \(i\) produces

\[
\Delta_i=\theta_i^{new}-\theta^{base},
\]

with dataset epoch roots, code hash, config hash, metrics, calibration, and signature. A model delta without its data lineage and validation record is inadmissible.

### 12.3 Quality-weighted robust aggregation

A conventional weighted update is

\[
\theta^{new}=\theta+\eta\sum_i w_i\Delta_i,
\]

where

\[
w_i\propto n_i q_i c_i d_i,
\]

using sample count \(n_i\), evidence quality \(q_i\), calibration quality \(c_i\), and distribution relevance \(d_i\).

For adversarial or unreliable fleets, use coordinate-wise median, trimmed mean, clipping, anomaly detection on updates, and a held-out validation gate. Every promoted model receives a new model identity and MINDEX lineage.

### 12.4 Prototype and embedding exchange

On low-bandwidth links, DIRTNet can exchange:

- class prototypes;
- anomaly centroids;
- compact covariance sketches;
- quantized adapters;
- knowledge-distillation targets;
- event fingerprints;
- model metadata and roots.

This often provides more value per byte than full model or raw-data transfer.

## 13. BlueSight, SINE, GANDHA, and FCI as DIRTNet sensory services

![DIRTNet multisensory edge stack](graphics/12_dirtnet_multisensory_edge_stack.svg)

### 13.1 BlueSight—visual and spatial intelligence

BlueSight combines directional and panoramic cameras, controlled blue-light biological response, LiDAR, radar, WiFiSense, pose, and edge AI. Its local products include boxes, masks, tracks, growth edges, depth maps, scene embeddings, motion/presence overlays, calibration state, and selected evidence frames.

The public roadmap calls for open-vocabulary detection, tiled high-resolution inference, segmentation and tracking, normalized APIs, MINDEX recording, and deployment on Jetson or Hailo-class accelerators. These should be treated as roadmap items until runtime/model evidence confirms each stage.

A local visual evidence event is

\[
e^{blue}_t=(objects,masks,tracks,depth,motion,embedding,q,provenance).
\]

### 13.2 SINE—acoustic intelligence

SINE's intended ladder is:

\[
\text{decode}\rightarrow
\text{STFT/PCEN/log-Mel/MFCC}\rightarrow
\text{activity/event windows}\rightarrow
\text{neural embedding}\rightarrow
\text{domain heads/OOD}\rightarrow
\text{prototype retrieval}\rightarrow
\text{evidence-fused transcript}.
\]

Its public workbench currently exposes an evidence-first interface and explicitly reports that no trained model artifact is proven in the displayed state. This is a strength in claim discipline: acoustic meaning must remain pending until model, prototype, fusion, or human evidence exists.

A DIRTNet acoustic event may send a compact 512-dimensional fingerprint, top peaks, domain probabilities, OOD score, and content-addressed raw window reference, rather than continuous raw audio.

### 13.3 GANDHA—chemical, odor, and particle intelligence

GANDHA combines VOC, VSC, gas, humidity, temperature, pressure, airflow, BME680/688/690-class channels, BMV080-class particulate sensing, optional spectroscopy/spectrometry, and odor libraries.

A compensated sensor model is

\[
z_t^{gandha}=E_\theta(r_t,T_t,RH_t,P_t,flow_t,age_t,calibration_t).
\]

A gas alert should require multi-channel or contextual verification when consequence is high. GANDHA outputs smell signatures, gas-verification records, particle event overlays, timelines, novelty scores, and raw-window references.

### 13.4 FCI and biological signal transduction

The Mycorrhizae biological-to-compute path is

\[
\text{stimulus}\rightarrow
\text{living biomass response}\rightarrow
\text{FCI transduction}\rightarrow
\text{artifact-controlled signal}\rightarrow
\text{motif}\rightarrow
\text{NLM state}\rightarrow
\text{computable primitive}\rightarrow
\text{governed next action}.
\]

![Mycorrhizae biological-to-compute transduction](graphics/11_mycorrhizae_biological_to_compute.svg)

A defensible single-biomass experiment must include sham stimuli, randomized order, environmental controls, contact impedance, blinded labels, repeated specimens, held-out days/devices, and a predeclared outcome.

A computable primitive may be:

- a state classifier;
- a threshold gate;
- an oscillator phase;
- an event detector;
- a response forecast;
- an optimization score;
- a controlled analog-computation result.

It should not be called language or intent without causal validation.

## 14. NatureOS and FUSARIUM

### 14.1 NatureOS—civilian and scientific surface

NatureOS exposes the DIRTNet stack to researchers, land managers, institutions, citizen-science programs, and commercial environmental operations. The public application surface includes device networking, NLM training, Earth simulation, scientific tools, APIs, SDKs, functions, and data exploration.

NatureOS emphasizes:

- reproducible science and model training;
- ecological and environmental monitoring;
- fleet/device operation;
- public, private, or institution-scoped data;
- dashboards and scientific workflows;
- governed automation and experiment design.

### 14.2 FUSARIUM—defense surface

FUSARIUM provides an operational environmental intelligence surface for defense users, integrating aerial, atmospheric, terrestrial, maritime, and infrastructure observations into mission context and CREP products. Its public architecture highlights field devices, local AI, passive acoustics, bioaerosol collection, edge data centers, MYCA/MINDEX mission memory, chain of custody, alerts, map layers, and analyst products.

### 14.3 Shared core, additive compartments

The science record should remain immutable and unmodified by defense interpretation. Mission classification, threat scoring, analyst assessment, and authority context should be additive records that reference the scientific source roots.

\[
Record_{mission}=f(Record_{science},mission,policy,analyst,model),
\]

without overwriting \(Record_{science}\).

## 16. DIRTNet threat model

### 16.1 Adversaries and faults

- compromised or cloned device keys;
- forged or replayed telemetry;
- GNSS/time spoofing;
- sensor poisoning or calibration manipulation;
- malicious model updates;
- eclipse or route-capture attacks;
- packet flooding and duty-cycle exhaustion;
- selective forwarding;
- stale checkpoints;
- privacy leakage through location or repeated keys;
- Byzantine gateway or compromised operator account;
- physical node capture;
- ordinary faults, partitions, battery loss, clock drift, and bit errors.

### 16.2 Controls

- secure boot and measured firmware where available;
- hardware-backed keys and rotation;
- signed sequence numbers and replay windows;
- multi-sensor plausibility checks;
- cross-node corroboration;
- rate and airtime budgets;
- transport encryption plus end-to-end signatures;
- model-update clipping, robust aggregation, and validation;
- key revocation and quarantine;
- privacy-preserving location precision;
- AVANI action gates and human review;
- Merkle proofs, independent checkpoint validation, and audit replay.

### 16.3 Trust score

Node trust is not a static label. A proposed score is

\[
T_i(t)=\sigma\left(
\alpha V_i+\beta C_i+\gamma A_i+\delta P_i
-\eta D_i-\mu S_i
\right),
\]

where \(V\) is signature/firmware validity, \(C\) calibration history, \(A\) agreement with independent evidence, \(P\) past predictive calibration, \(D\) detected drift, and \(S\) security anomalies.

Trust affects routing and aggregation but should never permit a high-trust node to bypass hard policy.

## 19. Implementation sequence

### Phase 0—contract freeze

- ratify node, message, sync, and checkpoint schemas;
- choose signature algorithms and hardware-key path;
- define canonical serialization;
- define MDP-to-Mycorrhizae translation;
- establish version and compatibility policy.

### Phase 1—single-node evidence chain

- sensor event → NMF/RootedNatureFrame → SHA-256 → signature → local log;
- local NLM event;
- epoch Merkle root and inclusion proof;
- MINDEX audit view.

### Phase 2—two-node partition and reconciliation

- HLC and sequence control;
- link emulator;
- store-and-forward;
- anti-entropy manifests;
- deterministic merge and duplicate suppression.

### Phase 3—multisensory services

- BlueSight event adapter;
- SINE evidence adapter, preserving “pending” status when no model proof exists;
- GANDHA event adapter;
- FCI controlled-perturbation adapter.

### Phase 4—distributed NLM and MYCA

- task placement;
- local model registry;
- prototype exchange;
- robust federated updates;
- MYCA distributed task graph;
- AVANI model/action promotion gates.

### Phase 5—NatureOS and FUSARIUM surfaces

- civilian science device/network view;
- defense mission and chain-of-custody view;
- shared evidence roots, additive access compartments;
- replayable demonstrations and external APIs.

## 20. Acceptance criteria

A DIRTNet reference implementation should not be called operational until it demonstrates:

1. signed observations and verified node identity;
2. deterministic duplicate rejection;
3. disconnected local sensing and inference;
4. later synchronization with no silent record loss;
5. verified Merkle inclusion proofs;
6. deterministic conflict and model-promotion rules;
7. measured bandwidth savings from compact edge products;
8. AVANI rejection of forged, stale, low-quality, or unauthorized inputs/actions;
9. complete MINDEX lineage from raw evidence to model inference to operator product;
10. NatureOS and FUSARIUM views generated from the same evidence roots under different policies.
